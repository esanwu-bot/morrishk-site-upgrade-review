## 1. 结论摘要

1. 客户版共 **227** 条功能条目，覆盖五个功能域：用户前台 60、商城运营后台 48、营销工作台 41、Ds Bit 产品知识工作台 34、平台管理中心 44。

3. 范围归属：保留 32、升级 66、新建 21、待确认 104、不纳入本期（建议排除）4。其中「纳入」合计 119 条。
4. 发现 **3 项客户承诺内容没有对应的冻结条目**：日志轮转与告警、BOM 清单、缓存切换与回退；客户版已在 5.5 节单列，需确认是否补入。
5. 发现 **16 项口径冲突或事实差异**，集中在语言集合、BOM 分期、三层闸门实现状态、帮助中心、价格与库存、后台覆盖矩阵。详见第 6 节。

### 2.3 替代依据的局限（必须由 Reviewer 知悉）

五份文档是**现状盘点**，不是目标建设清单。其条目包含 `NOT_FOUND` 与 `PARTIAL`，直接当作「冻结功能清单」会产生两个风险：

1. **把现状缺口误当建设承诺**：`NOT_FOUND` 条目可能属于本期新建，也可能根本不在本期。客户版因此引入「范围状态」，并将无批准依据者标为「待确认」。
2. **把已停用项误当功能**：少量条目只有注释代码或死代码。客户版标为「已停用」并列入不纳入本期。

因此，客户版的「新建」「升级」「待确认」是**基于以下次级依据的判定**，不是原始清单自带结论：

| 次级依据 | 用途 | 说明 |
|---|---|---|
| `01_business_plan` 与 `00_project_baseline/project_scope.md` | 业务目标与 P0/P1/P2 优先级 | P0 详情页与询盘；P1 搜索/SEO 与 Ds Bit；P2 BOM/AI Agent/Cross Reference |
| `newPlan/_v11/morrishk升级方案.md` 第 18 章 C01–C16 | 客户承诺与阶段 | 仅作为范围依据；**阶段标签不写入客户版**，以避免形成工期承诺 |
| `09_current_state_inventory/07-open-questions.md` | 待确认事项 | Q-01 已确认；Q-02～Q-60 仍开放 |
| `07_prototypes/admin/prototype-scope.md` | 旧后台 43 动作覆盖 | 仅用于交叉核对，不把原型覆盖当作已实现 |
| `02_technical_design/morrishk_technical_plan_v1.2.md` | 技术排除项 | OCR、实时库存/价格对接、移动 App 等不在本期 |

### 2.4 基线版本

本轮映射基于评审仓库当前 HEAD（`868cdb2`，P1-05 提交后）的五份盘点文档。若盘点文档后续修订，本记录需同步重算。
