## 文档说明

### 一、用途

1. 明确本项目五大功能域的功能条目、现状与范围归属。
2. 作为后续方案设计、开发排期、验收与变更控制的共同基线。
3. 将尚需客户决策的事项集中列出，避免在实施阶段反复返工。

### 二、现状口径

- 本文的「当前状态」依据本轮现状盘点形成，来源为历史生产数据快照与系统实现核对。
- 本轮未对生产环境进行实时探测。因此「已有（运行中）」表示该能力在历史快照中已存在且可与系统实现对应，**不代表本轮已对线上实时复核**。
- 「已具备（未确认上线）」表示系统内存在相应实现，但本轮未能确认其当前是否在生产中实际使用。
- 界面原型、演示数据与本地运行结果均不计为「已有」能力。

### 三、范围依据

本功能范围以五大功能域现状盘点为基础，结合双方已有业务目标、项目建设要求及待确认事项整理形成。现状盘点用于明确现有能力与功能边界，不直接代表全部功能均已批准纳入本期建设。第三章所列范围状态及第五章建设范围，作为本次提交客户确认的项目范围建议，以双方签署确认为最终依据。

「待确认」条目在双方确认前不构成承诺；「不纳入本期」条目为项目方建议的排除项，最终同样以双方签署确认为准。

### 四、范围状态定义

| 范围状态 | 含义 |
|---|---|
| 保留 | 现有能力继续使用，本次建议不做结构性改造 |
| 升级 | 现有能力保留，并按项目建议目标进行改造或补齐 |
| 新建 | 当前不具备，按项目建议列入本期建设内容 |
| 待确认 | 当前不具备或存在缺口，是否纳入、做到什么程度需双方确认；**在确认前不构成承诺** |
| 不纳入本期 | 项目方建议不在本期建设范围，最终以双方签署确认为准 |

### 五、当前状态定义

| 当前状态 | 含义 |
|---|---|
| 已有（运行中） | 历史生产快照中已存在并可对应 |
| 已具备（未确认上线） | 系统内有实现，是否在生产使用待核实 |
| 部分具备 | 只具备部分能力，或存在明确缺口 |
| 仅有界面方案 | 只有界面原型或演示，无实际业务实现 |
| 尚未具备 | 当前没有对应能力 |
| 已停用 | 功能已停止使用或未启用 |

## 第一章 项目建设目标

### 1.1 业务背景

Morrishk 是面向电子元器件采购方的 B2B 独立站。现有站点已积累商品、分类、内容与历史询盘数据，但存在以下业务问题：

1. 商品详情页的参数、库存、价格与交期信息不完整或不可追溯，影响采购方决策。
2. 站内搜索以型号前缀匹配为主，型号片段、错字与多语言场景命中不足。
3. 询盘分散在第三方表单、站内联系表单与购物车记录中，缺少统一编号、回执与渠道归因。
4. 内容发布缺少审核与发布授权，营销、社媒与邮件能力基本空白。
5. 后台以基础增删改为主，缺少权限、审计、审批与运营看板。
6. 产品资料（Datasheet）的解析能力已具备工程基础，但结果尚未进入可运营的商品与知识链路。

### 1.2 建设目标

1. **提升详情页转化**：让采购方在详情页完成参数查看、资料获取与询价，询盘可编号、可回执、可追溯。
2. **提升搜索与自然流量质量**：完整型号精确命中优先，同时支持片段与错字；完善 SEO 技术底座与多语言互链。
3. **打通产品知识与商品数据**：参数必须能回到原始文档的证据位置，未经审核的参数不得进入对外内容。
4. **建立可运营的营销与内容能力**：内容、SEO、社媒、视频与线索归因形成闭环。
5. **建立可治理的后台**：账号、角色、权限、审计、审批与配置可管理。
6. **支持五种目标语言**：英语、德语、日语、西班牙语、法语，默认英语。

### 1.3 本期不以以下结果作为承诺

1. 不承诺搜索引擎排名、流量或询盘数量的具体结果。
2. 不承诺第三方平台（搜索引擎、社媒、邮件服务商）的审核时限与接口稳定性。
3. 不承诺未经第七章确认的功能自动纳入。
4. 不承诺在本文件中未列出的客户账户、订单、报价等扩展能力。

## 第四章 业务协同关系

> 本章用于说明目标业务协同关系，不代表图中所有业务节点均已纳入本期建设。具体建设范围以第三章范围状态及第五章范围边界为准；待确认能力须经双方书面确认后方可纳入。
>
> 其中社媒发布、视频制作与 AI 内容生成等节点，需区分「系统功能」与「代运营 / 内容制作服务」：系统功能以第三章条目为准；内容策划、拍摄剪辑、账号日常运营等代运营服务不属于本确认书的功能交付范围。

### 4.1 链路 A：产品数据到商品详情页

```text
Datasheet 上传
  → 文档解析与表格重建
  → 参数候选生成
  → 证据绑定（页码 / 表格 / 行 / 单元格 / 坐标）
  → 人工审核
  → 参数进入商品详情页
  → 发布
```

边界：只有通过审核的参数才能成为详情页内容；未经审核的参数不得进入对外页面、SEO 文案或生成内容。

### 4.2 链路 B：产品知识到 SEO 与 GEO

```text
已审核参数与产品知识
  → 内容草稿生成或人工撰写
  → 内容审核
  → 发布授权
  → 站点发布
  → 搜索引擎与 AI 搜索表现回收
```

边界：内容审核通过不等于可以发布；发布需要独立授权与批次记录。

### 4.3 链路 C：内容到社媒与视频

```text
内容资产
  → 渠道适配
  → 审核
  → 排期
  → 发布
  → 引流至商品页或落地页
  → 形成询盘
```

边界：渠道发布失败不回滚商品数据与已产生询盘。

### 4.4 链路 D：询盘到归因与分析

```text
详情页 / RFQ / 联系表单 / 热卖位
  → 询盘统一编号与入库
  → 自动回执
  → 渠道与 UTM 归因
  → 有效询盘判定（排除垃圾与重复）
  → 转化漏斗与渠道报表
```

边界：垃圾询盘与重复询盘不计入有效询盘；渠道差异必须可逐条解释。

### 4.5 链路 E：平台治理

```text
账号 → 角色 → 权限 → 操作
  → 审计记录
  → 审批与发布授权
  → 配置与任务管理
```

边界：菜单可见不等于有操作权限；每个写操作都必须在服务端复核权限。

## 第六章 交付与验收原则

### 6.1 交付形态与责任边界

1. **保留**：以当前可核实的既有能力为基础继续使用，不承诺结构性改造。
2. **升级**：按本确认书确认的目标进行改造与补齐，交付可操作、可演示的系统能力。
3. **新建**：按确认范围从无到有建设，交付可操作、可演示的系统能力。
4. **既有功能发现的历史缺陷**：依据该缺陷是否属于升级范围，以及双方确认的缺陷处理边界，确定处理责任。

8. 本文的现状依据为历史生产快照与系统实现核对，本轮未对生产环境进行实时探测；验收时以当前环境的实际可用性为准。

### 6.2 验收原则

1. **按条目验收**：以第三章条目为最小验收单元，逐项确认可用性。
2. **按链路验收**：详情页询价、搜索、参数证据、内容发布、线索归因等跨模块链路需端到端验证。
3. **数据可复核**：参数必须能回到原始文档的证据位置；询盘必须有编号、回执与来源。
4. **权限可验证**：越权操作必须被服务端拒绝，不能只依赖界面隐藏。
5. **多语言可验证**：五种目标语言的页面、词条与互指关系需逐项检查。
6. **回归检查**：升级不得破坏既有 URL、既有内容与既有询盘数据。

### 6.3 不作为验收承诺的事项

1. 搜索引擎排名、收录速度、自然流量与询盘数量。
2. 第三方平台的审核时长、接口稳定性与政策变化。

### 6.4 验收证据

1. 功能演示与操作记录。
2. 关键链路的测试记录与问题闭环记录。
3. 数据核对结果，包括商品、分类、询盘与多语言页面抽样。
