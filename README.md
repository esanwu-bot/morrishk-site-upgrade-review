## 六、希望 Reviewer 重点复核的问题

1. **承诺与实现的可验证性**：追踪矩阵 C01–C16 的「验收指标」是否真的可测量、可复现，
   有无「看起来可验收、实际无法判定」的条目。
2. **千万级商品的索引与抓取策略**（技术方案 8.4）：Tier A–F 分级的判定规则、
   Tier D 276 万页面的处理，是否存在与 canonical / noindex / sitemap 信号冲突。
3. **缓存表切换方案**（3.8）：应用层双读灰度 + `RENAME` 收敛，回滚路径是否足够。
4. **询盘归因口径**（技术版 5.9.1）：拆为 S1 送达 / S2 校验 / S3 报表三态后，
   指标 B 的分母已改为「合格询盘数」并在分母层面剔除 consent 拒绝与 MP 失败。
   请复核这一处理是否消除了「差异率天然不为零」的问题，以及 3% 排除率阈值是否合理。
5. **数据库迁移风险**：`04_database/06_compatibility_scan.txt` 现采用两级模型——
   兼容性风险 **BLOCK=0 / BEHAVIOR=5 / NOTE=5**，迁移目标要求 **TARGET=2**（字符集、存储引擎）。
   请注意 `BLOCK=0` **仅指 DDL 结构层**，不覆盖 47 GB 数据内容、应用行为与迁移流程；
   数据层体检尚未进行（见该文件第八节）。请复核 TARGET 两项的处置优先级是否合理。
6. **排期与人日的自洽性**：四阶段人日区间与依赖关系是否存在被低估的并行冲突。
