## 三、设计体系

### 3.1 来源与裁定

存在两份设计文档，且**存在冲突**，本原型已做裁定：

| 文档 | 规定 | 本原型如何处理 |
|---|---|---|
| `stitch_morris_hk_website_redesignV2/DESIGN.md`（Morris Precision Industrial） | 品牌色 crimson `#dc2626`；禁止 pill 形状；禁止彩虹色徽章；圆角 2–4px；无阴影 | **作为视觉权威** |
| `prototype/design.md` v1.0 | 品牌色蓝色 `#0052CC`；emerald/amber/violet 语义徽章；`rounded-md` 6px | **作为交互与信息密度权威**，配色不采纳 |

裁定理由：`DESIGN.md` 时间更新（2026-11-14），且与同目录 `code.html`、`detail.html`
的实际实现一致；`prototype/design.md` 为 2026-10-22 的早期版本，其交互原则仍然有效。

> 另需说明：`DESIGN.md` 的 front-matter（Stitch 导出令牌）与正文「Colors」一节对
> canvas / surface 取值不一致（`#f8f9ff` vs `#f8fafc`）。本原型以**正文书面规范为准**。

## 四、原型标注系统（对应 Reviewer 第二轮检查项）

Reviewer 要求检查「HTML 中的假数据、占位链接、伪提交按钮是否被明确标注」。
本原型用**可切换的标注层**回答，而不是只在文档里口头声明。

**用法**：点右下角「原型标注」按钮，或按 `?` 键。

- 所有 mock 元素带 `data-mock="说明"` 属性；
- 开启后显示**琥珀色虚线框**与说明标签；
- 按钮上的数字即当前页 mock 元素数量；
- 每个页面底部有**原型状态条**，分四行：对应方案 / 实施阶段 / 已实现 / 模拟 / 待开发 / 本轮修改。

标注分三级：

| 标记 | 含义 |
|---|---|
| 已实现 | 交互可点、状态可切，接近真实行为 |
| 模拟 | 假数据、占位链接、伪提交，不可当真 |
| 待开发 | 本期不做或需后端配合 |

| 阶段 | Phase 1（核心） |
| 已实现 | BOM 行增删与序号重排、批量粘贴拆分（行/逗号/制表符）、50 行上限、邮箱与公司必填校验、附件类型与大小提示、字数计数、蜜罐字段、RequestId 生成、提交中禁用按钮、成功回执（LeadNo + RequestId）、失败状态保留内容、重复提交幂等提示 |
| 模拟 | 提交为前端模拟，不写库；LeadNo 随机生成；无服务端反垃圾评分、无邮件通知、无 GA4 回传 |

3. 「Demo: show failure state」按钮可查看失败态，失败态明确说明「用同一 RequestId 重试」。

## 六、已知缺口（主动声明）

| 缺口 | 说明 |
|---|---|
| 无真实数据 | 商品、库存、价格、聚合计数全部为静态 mock |

| SEO 仅预览 | 详情页给出 canonical 与 JSON-LD 预览，未接真实输出链路 |
| 后台未提交 | `admin/` 第二轮提交 |
| 移动端未真机验证 | 响应式断点已实现，未在真机验证触控热区与参数可读性 |

## 七、判定边界建议

| 判定 | 适用 |
|---|---|
| `PASS` / `PARTIAL` / `FAIL` | 信息架构、视觉体系、交互路径、表单规则、状态表达 |
| `NOT VERIFIABLE` | 前端代码质量、接口契约、性能、安全、权限、SEO 实际输出、真实数据下的表现 |

视觉通过不代表前端代码、接口、性能与安全通过，四者分开判定。
