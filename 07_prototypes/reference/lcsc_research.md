## 零、采集方法与证据边界

### 0.1 为什么需要特殊采集

LCSC 使用 Akamai 边缘防护。无头浏览器直连返回 `Access Denied`（TLS 指纹 + JS 挑战），
常规截图工具全部失败。本轮采用的路径：

1. `curl` 携带常规 UA 取回页面 HTML（Akamai 对 curl 放行，返回完整 SSR DOM）；
2. 解析 `<link rel="stylesheet">`，把 LCSC 的 CSS 下载到本地；
3. 把 HTML 中的 CSS 引用改写为本地路径，**剥离全部 `<script>`**（冻结动态行为，避免二次请求与反爬触发）；
4. 注入 `#snapshot-freeze` 样式（禁用动画与 sticky），
5. 用无头 Edge 渲染为 PNG。

脚本：`mysql_schema_audit/_work/lcsc/build_snapshot.py`（工作文件，不随本仓库提交）。

### 0.2 五个页面的证据强度（诚实标注）

## 一、首页

**URL** `https://www.lcsc.com/`
**截图** `lcsc_screenshots/01_home_2026-11-15.png`
**采集日期** 2026-11-15

### 1.1 信息架构（自上而下，实测 DOM 顺序）

| 序 | 区块 | 高度占比 | 内容 |
|---|---|---|---|
| 1 | 工具条（深色） | ~3% | Hot-Selling / Coupons / API / Language / Help / Contact Us |
| 2 | 主站头 | ~6% | Logo + 标语「More Asian Brands, Better Value」+ 全站搜索框（占位符 `Upload a BOM`）|
| 3 | 主导航 | ~4% | Catalog（蓝底实心按钮）/ Products / Manufacturers / RFQ/BOM / Deals / Custom Cables |
| 4 | 左侧分类树 | — | 悬浮于 Hero 左侧的推荐分类列表（Integrated Circuits、Discrete Semiconductors…）|
| 5 | Hero 三列 | ~18% | ①主 banner（促销主张 + 双 CTA）②促销卡 ③注册权益卡 |
| 6 | 统计条 | ~7% | `760,000+ In Stock` / `100% Authentic` / `High-Quality Asian Brands` / `570+ Authorized Brands` / `30-Day Return` |
| 7 | 四 Tab 快捷入口 | ~10% | Hot-Selling / Lightning Deals / Discount Parts / Popular Categories |
| 8 | 品牌-MPN-单价双栏表 | ~15% | 两列并排的「品牌 / 型号 / 单价」，右上 `Refresh` |
| 9 | 内容营销三卡 | ~12% | Custom Cables / PCB & PCBA / Acrylic PET Front Panels |
| 10 | 页脚五栏 | ~13% | Information / Tools / Customer Service / Electronic Components / Connect With Us |

### 1.2 关键交互

1. **搜索框兼作 BOM 入口**——占位符直接写 `Upload a BOM`，点击后进入上传流程。
   搜索与 BOM 询盘共用一个入口，这是 LCSC 最值得注意的产品决策。
2. **Catalog 是唯一实心按钮**——导航栏里只有 Catalog 用蓝色实心块，其余为文字链。
   通过唯一的实心块把"逛目录"设为默认动作。
3. **双 CTA**——Hero 主 banner 同时给"立即购买"与"查看详情"两个不同权重的按钮。
4. **`Refresh` 刷新**——价格表右上角提供显式刷新，回应"价格会变"这一 B2B 事实。
5. **四 Tab 切换**——Hot-Selling / Lightning Deals / Discount Parts / Popular Categories 在同一区域内切换，
   避免纵向堆叠。

### 1.3 组件模式

| 组件 | 形态 | 观察 |
|---|---|---|
| 页头三段式 | 深色工具条 + 白底主站头 + 白底导航 | 与 Morris 现方案一致，可确认结构合理 |
| Hero 三列 | `主 banner : 促销卡 : 权益卡` | 左重右轻，非等分 |
| 统计条 | 4–5 个「大数字 + 小标签」横向排列 | 数字用大字号 + 强调色，标签用 11px 灰 |
| 数据表 | 双栏并排，无表头底色区分 | 行高约 32px，密度高 |
| 卡片 | 白底 + 1px 描边 + 4px 圆角 | **无阴影**，与 Morris 的"数据面零阴影"一致 |
| 徽章 | 多色（绿 / 黄 / 红 / 蓝） | **Morris 明确不采用** |

### 1.4 值得借鉴

1. **搜索与 BOM 共用入口**——Morris 的首页搜索框同样应承担 BOM 上传/粘贴的入口职责，
   避免用户为了"传一个 BOM"另找按钮。
2. **唯一实心导航按钮**——导航层用"唯一实心块"表达默认动作，是低成本高收益的模式。
   Morris 应把"BOM 询盘"设为导航层唯一实心块（红色）。
3. **统计条作为信任背书**——4 个数字 + 短标签，一屏内建立可信度。Morris 可用
   「现货 SKU / 授权品牌 / 平均交期 / 报价响应时长」，但**数值必须是真实可核验的**。
4. **显式 `Refresh`**——价格与库存的时效性在 B2B 场景必须让用户可见可控。
5. **四 Tab 分区**——把 4 个并列的横向列表收进一个 Tab 组，比纵向堆 4 个表格更省首屏高度。

### 1.5 不适合 Morris

1. **深蓝顶栏 + 蓝色 Catalog 按钮 + 蓝色链接**——Morris 禁用蓝/绿/紫装饰色。
   全站主色只有 crimson，导航层实心块用 `--color-brand`。
2. **多色徽章**——LCSC 首页同时出现绿（有货）、黄（促销）、红（折扣）、蓝（新品）四种徽章。
   Morris 规定同一行最多两种颜色，其余靠文字区分。
3. **"Asian Brands"作为核心卖点**——这是 LCSC 的定位（亚洲品牌替代欧美品牌）。
   Morris 的定位是**稀缺料 / EOL 料的可得性**，卖点完全不同，不能照搬文案结构。
4. **促销卡 / Lightning Deals**——LCSC 是零售化电商节奏（限时折扣、优惠券）。
   Morris 是询盘型 B2B，价格需询价而非促销，**不设折扣倒计时、不设优惠券**。
5. **内容营销三卡（Custom Cables / PCBA / 面板）**——这是 LCSC 的增值加工服务线。
   Morris 无此业务范围，不复制。
6. **注册权益卡**——LCSC 用注册送券驱动注册。Morris 的注册动机是"报价跟踪 + 历史 BOM"，
   应改用功能价值而非优惠券。

### 1.6 对应方案章节

- 技术方案 `4.2 页面信息架构`（详情页入口在首页的挂载方式）
- 技术方案 `5.2 转化流程`（首页 → 询盘的路径）
- 技术方案 `8.8 Phase 1 就应完成的技术 SEO 基线`（首页结构化数据与首屏内容）
- 商务版 `三、升级蓝图`（首页在整体蓝图中的位置）

|---|---|---|

### 2.4 值得借鉴

1. **筛选栏在左、结果在右的双栏**——与 Morris 现方案一致（`--layout-sidebar` 248px），
   可确认该结构在同类站点是被验证过的。
2. **结果用表格而非卡片**——B2B 元器件检索的核心是横向对比（型号 / 品牌 / 封装 / 库存 / 价格 / 数量），
   表格是唯一能在一屏内完成对比的形态。**这一点直接支持 Morris 现有的高密度列表决策。**
3. **一屏 8 行**——在 36–40px 行高下，一屏 8 行是密度与可读性的平衡点，与 Morris 的
   `--table-row-h: 36px` 一致。

### 2.5 不适合 Morris

1. **无法确认其筛选维度是否包含"参数区间"**——Morris 需要电压/容差/温度等参数区间筛选，
   这是 Ds Bit 参数化子系统的直接产物，不能依赖通用分面筛选。
2. **分页形态未知**——Morris 受"千万级数据 + 游标分页"约束（技术方案 6.x），
   不能照搬"页码 1 2 3 … Next"的偏移分页。**这是硬约束，不因竞品怎么做而改变。**
3. **无证据支持其搜索语义**——Morris 要求"精确型号优先"（四层检索规则），
   这是 LCSC 未展示的能力，也无从判断，不作借鉴。

- 技术方案 `6.2 索引模型`
- 技术方案 `6.3 四层检索规则（R08）`——精确型号优先，**不受本页影响**

## 三、产品详情页

**URL** `https://www.lcsc.com/product-detail/...C8734.html`（STM32F103C8T6）
**截图** `lcsc_screenshots/03_product_detail_2026-11-15_render_incomplete.png`（**渲染不完整，仅存档**）
**采集日期** 2026-11-15
**证据强度** **中**——视觉不可判读；信息架构来自 `__NEXT_DATA__` 真实字段

### 3.1 为什么没有可用截图

该页由独立的 Next.js 应用承载（`static.lcsc.com/item/_next/static/css/*`），
与主站的 Nuxt 应用不是同一套样式体系，且组件级 CSS 按需注入。
离线快照只能拿到 3 个基础 CSS，页面呈无样式状态（见存档截图）。

**因此本节不给出任何视觉结论**（配色、间距、圆角、层级一律不描述）。
以下信息架构来自页面内嵌的 `__NEXT_DATA__` JSON，是**真实存在的数据字段**，可作为结构证据。

### 3.2 信息架构（依据 `props.pageProps.webData` 字段清单还原）

| 区块 | 对应字段 | 说明 |
|---|---|---|
| SEO / TDK | `tdkData` | 标题、描述、关键词独立维护 |
| 面包屑 | `parentCatalogList`、`parentCatalogId/Name`、`catalogId/Name` | 多级分类路径 |
| 型号标识 | `productCode`、`productModel`、`productNameEn`、`productKeyAttributes` | 内部编码与对外型号分离 |
| 品牌与封装 | `brandNameEn`、`encapStandard`、`isAsianBrand` | 封装为标准字段（如 `LQFP-48(7x7)`）|
| 库存 | `stockNumber`、`stockSz`、`stockJs`、`domesticStockVO`、`overseasStockVO`、`hasThirdPartyStock` | **国内/海外/第三方库存分列**，不是单一数字 |
| 价格 | `productPriceList`（6 档）、`productLadderPrice`、`ladderDiscountRate`、`reelPrice`、`currencySymbol` | 阶梯价 + 卷带价 + 折扣率 |
| 起订量 | `minBuyNumber`、`maxBuyNumber`、`minPacketNumber`、`minPacketUnit`、`split` | 最小购买量 / 最小包装量分离 |
| 参数 | `paramVOList`（11 项，含 `isMain`、`sortNumber`） | 每项有 `paramName/paramValue` 双语 + `isMain` 主参数标记 |
| 替代料 | `alternatePartList`（5 项，含 `matchType`、`hasAlternatePart`） | 替代料是**结构化字段**，不是人工推荐位 |
| 生命周期 | `productCycle`（实测值 `normal`） | 生命周期状态是**字段** |
| 资料 | `pdfUrl`、`pdfLinkUrl`、`productImages`（3 张：front/back/blank） | 数据手册 + 多角度图 |
| 认证 | `isRohsCert`、`rohsCertType`（`ROHS3`）、`rohsCertList`、`authenticationList` | 认证为列表，可多项 |
| 合规 | `eccn`（实测 `3A991A2`）、`htsMap` | 出口管制编码 + 海关编码 |
| 物流 | `productWeight`、`weight`、`foreignWeight`、`isHasBattery` | 重量与电池标识影响运输 |
| 跨境 | `isForeignOnsale`、`isForeignDisplay`、`isShowForeignPrice`、`currencyType` | 跨境可见性独立开关 |
| 样品 | `isSample`、`sampleNumber` | 样品可申请性与数量 |
| 促销 | `flashSaleProductPO`、`isPreSale` | 闪购与预售 |
| 常见问题 | `faqs` | 页面级 FAQ |
| 描述 | `productDescEn`、`productIntroEn` | 短描述 + 长介绍分离 |

**关键结构发现**：

1. **库存不是一个数字**——`domesticStockVO` / `overseasStockVO` / `hasThirdPartyStock` 三路并存。
   这对 Morris 有直接参考价值：Morris 的库存需区分"香港仓 / 供应商可调 / 期货"，
   而不是给一个笼统的"有货"。
2. **替代料是结构化字段**——`alternatePartList` 的每一项都带完整的库存、价格、封装、
   `paramVOList`、`matchType`。也就是说，替代料卡片能**独立渲染成一张完整的产品摘要**，
   而不是只给一个型号链接。
3. **生命周期是字段**（`productCycle`）——EOL 不是运营标注，而是数据模型的一部分。
   Morris 的"稀缺料/EOL"导向必须建立在同样的字段化基础上。
4. **参数带主次标记**（`isMain` + `sortNumber`）——参数不是平铺，而是有"主参数/次参数"与排序。
   这与 Morris 技术方案 4.2 的"核心参数优先、全参数折叠"是同一思路。
5. **合规字段齐全**——`eccn`、`htsMap`。Morris 面向香港转口贸易，这两个字段的实际价值更高。

### 3.3 关键交互

`[未验证]` —— 无可用视觉，不推测。

可确认的仅有：**阶梯价有 6 档**（`productPriceList` 长度 6，每档含 `ladder`、`productPrice`、
`extPrice`、`discountRate`），说明价格表是"数量区间 → 单价 → 小计"的三列结构。

### 3.4 组件模式

`[未验证]`。仅能从字段推断存在：面包屑、多图相册、参数表、阶梯价表、替代料列表、认证徽章组、
FAQ 折叠、数据手册下载。**形态与样式均未采集。**

### 3.5 值得借鉴

1. **库存分路**——国内 / 海外 / 第三方分列，让用户判断"能不能马上发"。
   Morris 应改为「香港现货 / 供应商可调 / 期货（Lead Time）」，这与 Morris 的实际履约能力一致。
2. **替代料卡片自包含**——每个替代型号都能独立渲染成完整摘要（库存、价格、封装、参数）。
   Morris 技术方案 4.6 的替代料规则版应确保数据结构支持这一点。
3. **参数主次 + 排序字段**——`isMain` 与 `sortNumber` 让"核心 8 项 + 全参数折叠"成为数据驱动而非硬编码。
4. **合规字段（ECCN / HTS）**——香港转口场景下是真实需求，且能显著降低询盘后的沟通成本。
5. **短描述与长介绍分离**（`productDescEn` / `productIntroEn`）——列表页用短描述，详情页用长介绍，
   避免一个字段两处妥协。

### 3.6 不适合 Morris

1. **`isAsianBrand` 作为一等字段**——这是 LCSC 的品牌叙事（亚洲品牌替代欧美）。
   Morris 不做品牌阵营叙事，字段无意义。
2. **`flashSaleProductPO` / `isPreSale` 闪购与预售**——零售化电商节奏，与询盘型 B2B 不符。
3. **卷带价（`reelPrice`）/ 最小包装单位（`minPacketUnit`）**——面向量产贴片采购。
   Morris 的客户结构以中小批量与稀缺料为主，暂不需要；若未来需要，应作为独立阶段而非首版。
4. **跨境可见性开关（`isForeignOnsale` 等）**——Morris 本身就是外贸站，不存在"国内版/海外版"
   双轨，无需这套开关。
5. **`smtLabel` / `isMro` / `isInfringement`**——LCSC 平台治理字段，Morris 无对应治理模型。
6. **不复制其七段式的具体切分方式**——Morris 的七段式（技术方案 4.2）是按"决策顺序"设计的
   （是什么 → 能不能用 → 有没有货 → 多少钱 → 能不能替代 → 证据在哪 → 下一步做什么），
   与 LCSC 的字段堆叠逻辑不同，**不得为对齐而改动**。

### 3.7 对应方案章节

- 技术方案 `4.2 页面信息架构`（七段式，**不因本节改动**）
- 技术方案 `4.3 参数渲染与降级链`
- 技术方案 `4.4 图片与资料资产修复`
- 技术方案 `4.5 询盘 CTA 布局`
- 技术方案 `4.6 替代型号（规则版）`

- 商务版 `四、P0-1：产品详情页升级`

## 四、BOM / RFQ 页

**URL** `https://www.lcsc.com/bom`
**截图** `lcsc_screenshots/04_bom_2026-11-15.png`
**采集日期** 2026-11-15
**证据强度** **强**

### 4.1 信息架构

| 序 | 区块 | 内容 |
|---|---|---|
| 1 | 页头三段式 | 同首页 |
| 2 | 二级页签 | `BOM Lists`（当前，蓝色下划线）/ `Quotes` |
| 3 | 双入口卡 | ①`Upload BOM File`（选中态，蓝色描边）②`Copy & Paste` |
| 4 | 上传说明 | `Support .xls, .xlsx and .csv files under 4MB` + `BOM Template` 下载链接 |
| 5 | `Key Features` 四宫格 | Bulk Import / Instant Data Access / Easy Editing / Real-Time Updates |
| 6 | 帮助行 | `Need help with the BOM List? See FAQ or Contact us` |
| 7 | 页脚五栏 | 同首页 |

### 4.2 关键交互

1. **双入口并列而非二选一**——`Upload BOM File` 与 `Copy & Paste` 是同一区域的两个并列 Tab，
   默认选中上传。**没有"必须先上传文件"的强制路径。**
2. **容量与格式前置声明**——`under 4MB`、`.xls/.xlsx/.csv` 写在入口卡内，不是上传失败后才提示。
3. **模板下载**——`BOM Template` 链接紧邻格式说明，降低"我的表格式不对"的失败率。
4. **四宫格解释"为什么用这个工具"**——不是功能列表，而是四条收益陈述
   （批量导入 / 即时取数 / 易编辑 / 实时更新），每条一句说明。
5. **`Quotes` 页签**——报价单与 BOM 列表同层级，说明"提交 BOM"与"查看报价"是一个连续流程的两端。

### 4.3 组件模式

| 组件 | 形态 | 观察 |
|---|---|---|
| 二级页签 | 文字 + 2px 下划线（当前项） | 无背景块，最轻量的页签形态 |
| 入口卡 | 大图标 + 标题 + 说明 + 链接，1px 描边，选中态描边加粗 | 两卡等宽并排 |
| 功能四宫格 | 2×2，标题加粗 + 一句说明 | 无图标、无底色，纯文字网格 |
| 帮助行 | 一行小字 + 两个文字链 | 极轻量，不占视觉权重 |

### 4.4 值得借鉴

1. **双入口并列**——Morris 的 BOM 询盘应同时给"上传文件"与"粘贴文本"，
   默认选中粘贴（Morris 的客户更多是复制几行型号，而非整理 Excel）。
   **顺序与 LCSC 相反**，因为客户结构不同。
2. **容量上限前置**——Morris 规定 `50 lines / 4MB`（技术方案 10.2），
   必须在入口处写明，而不是提交后报错。
3. **四宫格讲收益而非功能**——`Bulk Import` 后面跟的是"支持 800 行、4MB"，不是"支持批量"。
   收益必须带具体数字。
4. **页签形态极轻**——2px 下划线，无背景块。Morris 应沿用这种轻量页签，
   避免在 BOM 页出现第二套导航视觉。
5. **`Quotes` 与 `BOM Lists` 同层级**——提交与查看是一个流程，不该分散到两个入口。

### 4.5 不适合 Morris

1. **`800 lines` 上限**——Morris 规定 `50 lines`（技术方案 10.2 两阶段划分）。
   理由不同：Morris 首版是人工核价，50 行是可承诺的响应上限；LCSC 是系统自动匹配，
   可以吃 800 行。**不得为提高数字而放宽，那会破坏"30 分钟响应"的承诺。**
2. **`4MB` 上限**——Morris 同为 4MB（技术方案 10.3 附件安全规范），可直接沿用。
3. **`Instant Data Access`（56 万可订购料号即时取数）**——这是 LCSC 的规模优势，
   Morris 不具备，也不能宣称。
4. **无 LeadNo 概念**——LCSC 用账号体系承载"我的 BOM"，Morris 用 `LeadNo`（技术方案 5.3）
   让**未注册用户**也能凭编号跟踪。这是 Morris 的差异化，**必须保留**。
5. **无重复提交防护的可见证据**——LCSC 未见幂等提示。Morris 技术方案 5.5 要求
   "重复提交防护"，应在界面上明确反馈（"该 BOM 已于 x 分钟前提交，编号 L-xxxx"），
   而不是静默去重。

### 4.6 对应方案章节

- 技术方案 `10.1 结论` / `10.2 两阶段划分`（50 行上限的依据）
- 技术方案 `10.3 附件安全规范（S03）`（4MB、格式白名单）
- 技术方案 `5.4 表单规则`
- 技术方案 `5.5 反垃圾与幂等`（LeadNo、重复提交防护）
- 商务版 `六、P0-3：询盘转化`

### 5.4 值得借鉴（仅一条，且有证据）

1. **报价单以列表形态存在，且与 BOM 提交同页**——提交与查询不跨越两套导航。
