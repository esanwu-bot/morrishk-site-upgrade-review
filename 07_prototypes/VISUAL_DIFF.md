# 视觉迁移差异评估（v1.4 → v1.5.1）

> **本文不主张"像素完全一致"。** 上一版（v1.5）用调色板统计与人工目视得出"八个主色一一对应、
> 色值完全相同"的结论，该结论**不成立**——它只覆盖了主色，没有覆盖间距、字号、阴影、层级，
> 也没有做过逐像素差分。本轮改为给出**实测数字 + 逐条取值清单 + 差异原因**。

## 一、结论（先说结果）

1. **Token 化迁移已完成**：`tokens.css` 之外的样式声明中，字面色值为 **0**（见 `TOKEN_AUDIT.md` 第 A 节）。
2. **色相方向未变**：仍是 crimson + 中性灰阶 + 功能琥珀，未引入蓝 / 绿 / 紫。
3. **视觉并非像素一致**：同视口逐像素差分实测差异 **3.11% – 25.59%**（可见差异 2.99% – 15.15%）。
4. 差异有三类**已定位**的来源，全部可解释、可逐条核对：

   | 来源 | 数量 | 性质 |
   |---|---|---|
   | 间距 / 字号 / 阴影 / 层级吸附到 4pt 与 Token 刻度 | 41 条取值变更 | **有意为之**，属设计系统统一 |
   | 库存状态组件替换（有货加 `✓` + 文字，可用量表少一行） | 16 处 | **有意为之**，本轮整改项 |
   | 入口页设计体系说明文字改写 | 1 处 | **有意为之**，文字内容变更 |

5. **不能从本文推出**"设计已通过"或"视觉无回归"。本文只回答"改了什么、差多少、为什么"。

## 二、方法与可复现性

| 项 | 值 |
|---|---|
| 旧版快照 | `git archive v1.4-review` 导出的完整仓库树 |
| 新版 | 本轮工作区 `07_prototypes/`（= 本地 `prototype/redesign/`） |
| 浏览器 | Microsoft Edge（Chromium）`--headless=new --disable-gpu --hide-scrollbars` |
| 视口 | 1440 × 2600，`--force-device-scale-factor=1`，两版完全相同 |
| 加载方式 | 本地 `python -m http.server` + `http://127.0.0.1`（不用 `file://`，避免中文路径与子资源加载差异） |
| 等待 | `--virtual-time-budget=4000` |
| 页面 | index / home / product_detail / search / inquiry，各 1 张，共 10 张 |
| 差分脚本 | `mysql_schema_audit/tools/pixel_diff.py` |
| 取值比对脚本 | `mysql_schema_audit/tools/css_value_diff.py` |

差分口径：两图尺寸必须完全一致（否则报错，不做缩放对齐）；三通道任一不同即计为"严格差异"；
`|ΔR|+|ΔG|+|ΔB| > 24` 另计为"可见差异"。

## 三、像素差分实测

| 页面 | 尺寸 | 严格差异像素 | 占比 | 可见差异像素 | 占比 | 差异行段数 |
|---|---|---|---|---|---|---|
| `index.html` | 1440×2600 | 709,741 | 18.957% | 371,013 | 9.910% | 34 |
| `home/index.html` | 1440×2600 | 188,715 | 5.040% | 146,551 | 3.914% | 37 |
| `product_detail/index.html` | 1440×2600 | 958,099 | 25.590% | 567,145 | 15.148% | 65 |
| `search/index.html` | 1440×2600 | 206,302 | 5.510% | 133,321 | 3.561% | 28 |
| `inquiry/index.html` | 1440×2600 | 116,590 | 3.114% | 111,976 | 2.991% | 37 |
| **合计** | 5 × 3,744,000 | 2,179,447 | 11.641% | 1,330,006 | 7.105% | — |

**这不是抗锯齿噪声。** 若差异仅来自文字抗锯齿，差异像素应集中在字形边缘、占比通常 < 1%。
实测 3.11% – 25.59%，且差异呈**整段连续色带**（详情页有 65 个差异行段），符合"内容整体位移"的特征。

## 四、累计纵向位移（关键证据）

间距从 v1.4 的"手工零值"（9px / 10px / 14px / 7px）吸附到 4pt 刻度（8px / 12px / 16px / 6px）后，
每张卡片、每个表头都矮或高几像素，**误差沿页面累加**，导致下半页内容与旧版不再逐行对齐。

在同一坐标系下测得的局部纵向偏移（正数 = 新版内容更靠上）：

| 页面 | y≈200 | y≈900 | y≈1600 | y≈2200 |
|---|---|---|---|---|
| `product_detail` | 0 px | +21 px | +24 px | **+30 px** |
| `home` | 0 px | +4 px | +4 px | +4 px |
| `search` | 0 px | +14 px | （该区域为空白，无有效对齐） | — |

这解释了为什么"顶部几乎看不出差别、越往下差异越大"。

## 五、取值变更逐条清单

完整清单见 `reference/prototype_shots/CSS_VALUE_DIFF.md`（由脚本生成，可重跑）。
统计口径：两版 `proto.css` 在共同选择器下共 703 条声明，其中 **652 条取值等价**
（仅书写差异，如 `#fff` → `#ffffff`、`var(--primary)` → `var(--color-brand)`），
**51 条真实变更**：

| 类别 | 条数 | 典型变更 | 判断 |
|---|---|---|---|
| 间距 | 21 | `.card-hd` `10px 14px`→`8px 16px`；`.card-bd` `14px`→`16px`；`.pop` `10px`→`12px`；`.chip` `3px 7px`→`2px 6px`；`table.spec th` `7px 10px`→`6px 10px` | 吸附 4pt 刻度，有意 |
| 颜色 | 10 | `.errmsg` / `.is-error` `#dc2626`→`#991b1b`（danger 用 red-800，对比更强）；`body.annot` 虚线 `#f59e0b`→`#b45309` | 有意（对比度提升） |
| 排版 | 8 | `.logo .sub` 字距 `.12em`→`.04em`；`.btn` / `.mainnav a` 字距 `.01em`→`0`；提示条行高 `17px`→`18px` | 吸附 Token 刻度，有意 |
| 阴影 | 4 | 单层 `0 10px 15px -3px` → 双层 `0 10px 15px -3px + 0 4px 6px -4px`；`.bulkbar` 改用 `--shadow-bar` | 统一为三档阴影，有意 |
| 层级 | 4 | `.pop` `60`→`40`；`.bulkbar` `80`→`60`；`.facet-drawer` `100`→`80`；`table.grid th` `2`→`10` | 归入 `--z-*` 体系，有意 |
| 动效 | 2 | `.12s` / `.16s` → `120ms` / `180ms` + `cubic-bezier` | 统一缓动，有意 |
| 其他 | 2 | `.hub` 高 `36px`→`32px`（`--input-h`） | 有意 |

**说明**：`.select { height: 32px }` 在比对表里显示为"删除声明"，实际是并入了
`.input, .select { height: var(--input-h) }`，渲染结果相同，属工具的选择器字符串匹配限制，非真实删除。

## 六、库存状态组件替换（本轮整改项）

| 位置 | v1.4 | v1.5.1 |
|---|---|---|
| 搜索页 Stock 列 | `<span class="dot dot-ok"></span> 12,480` | `✓ IN STOCK 12,480` |
| 搜索页低库存 | `badge-crit`（红）`Low stock` + `dot-warn`（琥珀） | `badge-warn`（琥珀）`Low stock` + `! LOW STOCK 240` |
| 详情页可用量 | `● 12,480`（香港换行成两行） | `✓ IN STOCK 12,480`（单行，表格少一行） |
| 详情页同系列 | `● 5,120` / `● 310` / `● 0` | `✓ IN STOCK 5,120` / `! LOW STOCK 310` / `× OUT OF STOCK 0` |
| 首页现货表 | 同上 | 同上 |
| 搜索页 `Exact` 徽章 | `badge-crit`（红，语义错误） | `badge-solid`（中性深色） |

详情页可用量表由 3 行变 2 行，是本页差异占比最高的单点原因之一（其余为累计位移）。

## 七、本文未覆盖的事项（必须一并阅读）

1. **只覆盖一个内核**：Chromium（Edge headless）。Firefox / Safari 未测。
2. **只覆盖一个视口**：1440×2600。窄屏、平板、真机均未测，移动端**未重新截图**。
3. **只覆盖首屏 2600px**：页面更长时超出部分不在差分范围内。
4. **不含交互态**：hover / focus / 展开替代料 / 打开浮层等状态未截图。
5. **字体渲染依赖本机**：换机器或换字体版本会产生系统性差异，本文结论**仅在相同环境下可复现**。
6. **差异为 0 也不等于视觉正确**：只证明两版渲染一致，不证明设计合理。
7. **未做对比度工具化扫描**：颜色变更的对比度影响为人工估算。

## 八、给 reviewer 的判断依据

如果评审标准是"**视觉必须与 v1.4 逐像素一致**"——**本轮不通过**，实测差异 11.64%（严格口径）。
如果评审标准是"**视觉体系成立、差异可解释、无未记录变更**"——本文提供了逐条清单与实测数字，
请据此判断这 51 条取值变更是否可接受。

乙方立场：这 51 条变更是**设计系统统一必然的副作用**（把手工零值吸附到 4pt 与 Token 刻度），
不是无意的回归。若 reviewer 要求视觉零差异，需要回退到 v1.4 的零散取值，
那等于放弃 Token 刻度——两者不可兼得，需要 reviewer 明确取舍。
