## 一、如何打开

直接双击 `admin/index.html`，或：

```
file:///<repo>/07_prototypes/admin/index.html
```

- 不需要 Node、构建、后端或数据库。
- 所有路由都是 hash 路由（`#/products` 等），刷新后停留在当前页。
- 推荐 Chrome / Edge 最新版；桌面优先，≥ 1024px 为完整布局，≤ 1024px 侧栏折叠为抽屉。
- 唯一的外部依赖是仓库内 `../assets/` 的字体与图标；无网络请求、无 CDN 运行时依赖。

## 二、核心概念

一个入口、两个业务中心、一层共享知识、一套数据与增长工作台：

```
工作台（经营概览 · 待办 · 通知 · 指标）
├── 商城运营：商品 / 品牌 / 分类 / 库存 / 详情页 / 搜索 / 询盘 / 网站基础
├── 营销运营：总览 / SEO / GEO / 内容 / 社媒 / 日历 / 视频 / 活动 / 数据分析
├── 产品知识：Ds Bit 资产 / Datasheet / 参数审核 / 知识库 / 版本 / 内容生成
└── 系统管理：用户 / 角色权限 / 审批 / 审计 / 设置
```

四条业务链路在页面中显式呈现：

| 链路 | 路径 | 边界 |
|---|---|---|
| A 产品数据 → 商品详情页 | Ds Bit 解析 → 参数标准化 → 证据校验 → 人工审核 → 详情页 → 发布 | 仅 Verified 可成为详情页内容候选 |
| B 产品知识 → SEO / GEO | 已审核知识 → 内容生成 → 人工审核 → 发布 → Search Console / GA4 回填 | 待审核参数不得写入正文 |
| C 产品知识 → 社媒与视频 | 生成 → 审核 → 排期 → 发布 → 引流询盘 | 发布失败不回滚商品与询盘 |
| D 营销数据回流 | 询盘 → 渠道 → UTM → 漏斗 → GA4 → 有效询盘 | Spam / 重复不计入有效询盘 |

## 四、核心交互（均已浏览器验证）

1. **路由与导航**：hash 路由、面包屑、当前项高亮、移动端菜单开合、导航计数（待办 / 通知 / 询盘 / 待审核 / 审批）。
2. **筛选与搜索**：商品/文档/审计/询盘/活动支持关键字 + 状态下拉；计数显示「显示 X / 共 Y 条」；无结果行提示。
3. **Tab 状态**：每个页面的 Tab 写入内存状态，重渲染后保持；带 `statusFilter` 的 Tab 同步过滤表格。
4. **抽屉**：商品、内容、询盘、排期、文档、参数、品牌、分类、审批、用户、视频、活动、GEO 草稿均可打开与关闭（`Esc` / 遮罩 / 关闭按钮）。
5. **弹窗表单**：新增商品/内容/排期/视频/活动、邀请用户、新增页面/品牌/属性/同义词/热门词、上传 Datasheet、版本差异、全局搜索、帮助。
6. **动作反馈**：通过、拒绝、退回、发布、排期、重试、启停、权限切换、保存设置等都会立即更新视图并弹 Toast；关键动作追加一条 Demo 审计。
7. **图表**：内联 SVG 折线、迷你趋势、漏斗、环形图；无图表库、无外部请求。
8. **全局搜索**：顶栏或 `/`、`Ctrl/Cmd+K` 聚焦；回车弹出跨商品/内容/询盘/文档/用户结果，点击跳转对应模块。
9. **CSV 导出**：本地 Blob 生成，文件名与列随数据集变化；导出的是 Demo 数据，不上传服务器。
10. **内容生成**：点击「生成草稿」后展示排队 → 检索 → 生成 → 校验四步，最后给出草稿与证据引用，可保存到内容库。
11. **原型标注**：右下角 FAB / `?` 切换 `data-mock` 琥珀虚线；计数实时更新；图例说明「已实现 / 模拟 / 待开发」。
12. **每页底部状态表**：对应方案、实施阶段、已实现、模拟、待开发、本轮修改。

## 五、Mock 数据与标注规则

- 所有业务数据（商品、库存、参数、询盘、内容、社媒、视频、活动、审计、指标）均为 **Demo 抽样**，不代表线上真实数据。
- 假数据、伪动作、未接接口的按钮通过以下方式标注：
  - 页面级 `Demo` chip；
  - 元素级 `data-mock`（开启标注后显示琥珀虚线）；
  - 页面底部状态表的「模拟 / 待开发」行；
  - Toast 文案里明确「（Demo）」。
- 不虚构价格：所有商品与库存页统一显示 `Request Quote`。
- 未审核参数统一显示「待审核 / Needs Review」，不得出现在前台预览、SEO 文案或生成内容中。
- 社媒「未连接（Demo 状态）」、GA4 / Search Console「未连接」、Ds Bit「未连接（Demo 快照）」、发布队列「未接入（Demo）」均为当前原型状态，不接入真实 Token / API；目标架构与当前状态在页面上分开描述。
- 参数证据链固定展示 15 个字段：DocumentId、ParseRunId、DocumentVersion、DocumentType、DocumentSubject、RawLabel、RawValue、NormalizedValue、ValueKind、Conditions、PageNo、TableId、RowId、CellBBox、ReviewStatus，并单独展示商品↔Datasheet 适用性判定。

## 六、设计决策

1. **单页 Hash 路由**：一个 `index.html` 覆盖全部菜单，满足「直接打开、无构建、全部可点」的交付约束；刷新不掉页。
2. **复用 Morris Design System**：`tokens.css` 提供颜色/间距/字号；`admin.css` 零字面色值，状态色走语义 Token。
3. **状态三通道**：颜色 + 图标 + 文字同时表达（`UI.pill` / `UI.stock`），不依赖单一颜色。
4. **表格优先、抽屉补充**：列表用于扫描与批量操作；详情/编辑进入右侧抽屉，避免跳页丢失上下文。
5. **三层质量闸门**：PIPELINE_PASS、CONTENT_APPROVED、RELEASE_APPROVED 分开记录，但依赖上游通过（PIPELINE_PASS → CONTENT_APPROVED → RELEASE_APPROVED），不得合并为 Verified；参数级 ReviewStatus 只代表该参数审核状态，详情页与生成内容分别展示三道闸门。已发布商品展示历史验证快照，不把当前未运行写成已通过。
6. **证据 ≠ 适用性**：CellBBox 与置信度只证明文本位置和识别把握，不证明参数适用于该 MPN；适用性需结合 MPN 匹配、文档主体与测试条件。
7. **权限隔离显式化**：四个角色 × 九个业务域的矩阵，切换只改当前前端状态，真实 RBAC 待后端落地。
8. **系统边界可见**：Ds Bit 独立引擎、只读接入；GA4 / Search Console / 社媒未连接；任务队列仅展示状态。
9. **可复核性**：每页保留状态表与标注层，Reviewer 可区分「已实现交互」与「模拟数据/待开发」。

## 七、明确不做（非目标）

- 不修改任何现有 Yii2 代码、数据库、生产服务器、Nginx、PHP / MySQL 配置。
- 不创建真实营销发布接口、不连接真实社媒、不接入真实 GA4、不创建生产任务队列。
- 不复制 Ds Bit 解析核心代码；后台只设计数据管理与使用入口。
- 不把 ThinkPHP 作为新后台后端；不把全部功能做成单一大模块。
- 不新增中文 / 印尼语前台页面；新站语言固定 en / de / ja / es / fr，默认 en；旧站 `messages/` 保持不动。
- 交付 HTML 原型后停止，不进入 React / API / 数据库 / 真实后台开发。
