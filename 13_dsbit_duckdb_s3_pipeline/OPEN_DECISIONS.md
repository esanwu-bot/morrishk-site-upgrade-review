# 未决事项（OD-01 ~ OD-18）

| 级别 | 含义 |
|---|---|
| **P0** | 阻断 Stage A / Stage B 启动；不裁定不得进入实现 |
| **P1** | 阻断 Stage C；可在 Stage B 期间裁定 |
| **P2** | 不阻断，但影响成本、可维护性或长期合规 |

决策人缩写：**R** = Reviewer；**A** = 甲方（Morrishk）；**B** = 乙方（贤戈网络）；**R+A** = 共同确认。

## P0（阻断启动）

### OD-01 对象存储选型与区域

| 项 | 内容 |
|---|---|
| 问题 | 使用 DigitalOcean Spaces、阿里云 OSS，还是自建 MinIO？计算与存储是否必须同区？是否允许跨境？ |
| 影响 | 决定直读是否可行、出口费、合规、S3 条件写语义、Object Lock 可用性 |
| 选项 | A. DO Spaces（与现有 G0 同厂）+ 同区计算；B. 阿里云 OSS + 国内计算；C. 自建 MinIO（仅本地/私有云）；D. 混合（热数据 Spaces，冷数据归档 OSS） |
| 建议 | 试跑阶段选 **A 或 B 的同区组合**；MinIO 只用于本地验证；不做跨区直读 |
| 决策人 | R + A |
| 触发 | Stage A 之前 |
| 备注 | 现有 G0 在 DO NYC3；国内数据合规需单独评估 |

### OD-03 任务领取机制

| 项 | 内容 |
|---|---|
| 问题 | 用「确定性分片」还是「对象存储条件写抢占」？目标存储是否可靠支持 `If-None-Match: *`？ |

### OD-06 ID 与指纹的归一化

| 项 | 内容 |
|---|---|
| 问题 | `document_id` 只取 SHA 前 12 位（碰撞概率非零）；源码行尾 CRLF/LF 会让 `parser_fingerprint` 跨平台不同 |
| 影响 | 对象键与索引若用短 ID 可能冲突；Windows/Linux 指纹不可比 |
| 选项 | A. 对象键与索引一律用完整 SHA-256，`document_id` 只做人读；B. 扩展 `document_id` 长度（破坏既有 ID）；C. 指纹按 LF 归一化后计算 |
| 建议 | **A + C**，不改变既有 `document_id` 语义 |
| 决策人 | R |
| 触发 | Stage A 实现前 |
