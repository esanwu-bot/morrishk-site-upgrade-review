## 摘要

本项目不是一次单纯的“网站改版”，而是围绕一个业务目标重建获客链路：**让目标市场的采购方能够找到 Morrishk、看懂产品、建立信任、提交真实采购需求，并让这些需求可被追踪、审核和跟进。**

项目分三层推进：

1. **基础层**：修复并升级既有独立站与后台，统一商品主数据、分类、状态和发布门禁，保证“能被搜到、能正确展示、能承接询盘”。
2. **增长层**：以重点产品、关键词和落地页为抓手，建设可持续的 SEO 与内容资产。
3. **运营层**：上线后按月进行关键词、页面、内容、技术检查、监测和整改，用交付物和证据验收，而不是用排名承诺验收。

范围基线：既有 227 项功能需求中，**119 项纳入**（保留 32、升级 66、新建 21），**104 项待确认**，**4 项建议不纳入**；另新增 **15 项交付**（3 项软件功能、9 项服务交付、3 项持续运营）。所有金额、日期、目标市场、重点产品和关键词数据均待确认，本文件不代填。

## 一、项目背景与业务目标

### 1.1 背景

Morrishk 面向电子元器件采购场景，现有独立站承载产品展示与询盘入口。随着目标市场变化和搜索环境变化，站点需要同时解决三类问题：

- **可见性**：目标采购方能否在搜索与站内导航中找到对应型号、品牌、分类和替代料；
- **可信度**：产品参数、库存/价格/交期口径、Datasheet 与证据能否支撑采购判断；
- **转化力**：询盘入口、表单、归因和跟进能否把访问转化为有效采购询盘。

### 1.2 业务目标

项目核心目标：**增加目标市场的有效采购询盘**。

为避免把“建站”“流量”误当成结果，项目明确区分以下层级：

| 层级 | 含义 | 是否作为结果承诺 |
|---|---|---|
| 访问 | 目标市场用户到达站点 | 否，业务观察 |
| 商品浏览 | 用户查看具体型号/分类/品牌 | 否，业务观察 |
| 询盘提交 | 表单成功提交（含重复、待审核） | 否，业务观察 |
| 有效采购询盘 | 经业务审核确认具备采购意图与可联系信息 | 验收口径，非结果承诺 |
| 报价 | 已向客户发出报价 | 否，业务观察 |
| 成交 | 已成交订单 | 否，业务观察 |

### 1.3 项目不承诺的内容

- 不承诺固定搜索排名、自然流量、询盘数量或成交金额；
- 不承诺迁移后排名、收录或流量不下降；
- 不承诺未经客户确认的目标市场、重点产品、关键词或页面数量；
- 不以“访问增长”替代“有效询盘增长”。

## 二、目标市场与有效采购询盘定义

### 2.1 目标市场

目标市场由客户销售方向、供货能力、现有流量与产品数据共同确定。客户未确认前，本项目**不指定具体国家/地区为正式目标市场**，相关字段在 03 与 08 中标记 `PENDING`。

### 2.2 目标语言

项目目标语言已确定为 **en / de / ja / es / fr**：

- 第一阶段只交付 **en**；
- de / ja / es / fr 为后续阶段，不取消；
- id、zh 不纳入当前五语规划，除非双方书面变更；
- 第一阶段 URL 不带语言前缀，不输出任何 hreflang（含 x-default）；后续语言真实发布后，再配置对应页面的 hreflang 双向关系。

该语言清单已由 Reviewer 关闭，不再列为待确认事项。

### 2.3 有效采购询盘定义

有效采购询盘指同时满足以下条件的询盘：

1. 具备可联系的采购方信息；
2. 有明确型号或真实采购需求；
3. 经业务审核确认。

以下不计入有效采购询盘：垃圾提交、测试提交、重复提交、明显无采购意图的提交。重复、机器人、内部测试数据必须单独标记，不得混入有效询盘统计。

询盘状态流转：**新询盘 → 待审核 → 有效询盘 → 已分配 → 已报价 → 已成交 / 已关闭**。

## 五、SEO 与询盘增长策略

### 5.1 总体路径

以“**技术可抓取 → 页面可承接 → 内容可信任 → 询盘可归因 → 运营可迭代**”为主线：

1. **技术 SEO 基线**：状态码、canonical、robots、Sitemap、结构化数据、移动可用性、Core Web Vitals；
2. **产品页面（PDP）**：以 MPN + Brand 为业务身份，确保型号词、替代词、参数词有可索引且可询价的落地页；
3. **分类/品牌/系列页**：承接品类采购、品牌采购与系列选型意图；
4. **技术内容**：替代料、选型、应用场景、参数解释，建立专业信任；
5. **采购承接页**：明确 CTA、表单、响应机制与追踪；
6. **归因与运营**：事件字典、有效询盘审核、月度复盘与整改。

### 5.2 页面 SEO 规范

页面级 SEO 元素沿用《Morrishk SEO Elements and Page Spec V1.0.xlsx》的 **11 类页面 × 28 项规范（308 条）**，本项目不重复 308 行明细，只引用规则。核心规则：

- Hreflang 仅在真实翻译页面之间输出；第一阶段仅 en，不输出虚假 hreflang；
- Canonical 与 noindex 不组合指向他页；
- PDP 仅在 `RELEASE_APPROVED` 状态下允许被索引；
- 搜索页 `noindex,follow`，不进入 Sitemap；
- Sitemap 只含可索引的规范 URL。

### 5.3 询盘链路

访问 → 商品浏览 → 询价点击 → 表单开始 → 表单提交 → 有效询盘审核 → 分配 → 报价 → 成交。每一环节均定义事件、字段与责任方，避免“只看提交量、不看有效性”。

## 八、旧域名与 URL 迁移

迁移遵循“**先盘点、后映射、再验证**”，未取得旧 URL 数据前不声称映射完成。

### 8.1 工作范围

1. 域名、DNS、SSL、CDN 所有权与管理关系；
2. 旧 URL 全量盘点（来源、数量、状态）；
3. 旧 URL 与新 URL 人工映射（**禁止自动 301**）；
4. 301 / canonical 规则，目标最终 200、绝对自指、无链式；
5. Hreflang 规则（第一阶段不输出）；
6. Sitemap / robots 更新；
7. 404 / 410 / 软 404 检查；
8. 上线前后回归：全量盘点 + 关键 URL 100% + 其余按旧 URL 总量分层抽样；
9. 上线后监测与回滚预案。

### 8.2 回归抽样规则

| 旧 URL 总量 | 全量盘点 | 关键 URL 核验 | 其余抽样建议（待负责人确认） |
|---|---|---|---|
| ≤ 1,000 | 100% | 100% | 100% |
| 1,001–10,000 | 100% | 100% | ≥ 30% 且不少于 1,000 |
| 10,001–100,000 | 100% | 100% | ≥ 5,000 或按类型分层 |
| > 100,000 | 100% | 100% | ≥ 10,000 + 按类型/流量分层 |

关键 URL 始终 100% 核验，包括首页、主要分类/品牌、重点产品、主要落地页、历史高流量 URL、已有外链 URL 和所有计划 301 的源 URL。**不设固定回归条数，不承诺迁移后排名/收录/流量不下降。**

## 十、每月 SEO 运营

持续运营与一次性开发分离，避免重复计费。月度运营包含 11 项工作：

1. 关键词研究与复核；
2. 重点产品页面优化；
3. 品牌/分类页面优化；
4. 新增落地页；
5. 内容策划与生产；
6. 技术 SEO 检查；
7. 抓取/索引监测；
8. 询盘/有效询盘与来源分析；
9. 页面转化分析；
10. 问题整改与复核；
11. 月度报告与下月计划。

每项列明频率、交付物、验收方式与费用属性。工作数量与工时按三值管理：

- **Agent 建议值**：仅作编制建议；
- **负责人确认值**：内部审核口径；
- **合同承诺值**：以双方签署合同/订单为准。

未经负责人确认的数量或工时，不作为乙方承诺。具体见 `05_COMMERCIAL_QUOTATION.xlsx` 的 C 部分与 `03` 第 10 章。

## 十三、验收与持续优化

### 13.1 验收对象

验收对象是**工作、交付物和质量**，不是排名或询盘结果：

| 验收对象 | 标准 | 证据 |
|---|---|---|
| 页面清单 | 编号、URL、关键词、CTA、追踪、状态齐全 | 清单与发布记录 |
| 关键词台账 | 类型、意图、来源、状态、目标页齐全 | 台账导出 |
| 页面 SEO | Title/Description/Canonical/Robots/H1/Schema 符合规范 | 抓取/校验报告 |
| 迁移 | 映射台账、301/404/410 规则、全量盘点/关键 URL/分层抽样 | 回归报告 |
| 追踪 | 事件字典、字段、抽样日志 | 事件核对记录 |
| 月度运营 | 计划、工作记录、月报、整改闭环 | 月报与整改单 |
| 技术支持 | 问题分级、响应、复测 | 工单/复盘 |

### 13.2 缺陷分级与整改（建议值，非最终 SLA）

| 等级 | 定义 | 建议响应 | 说明 |
|---|---|---|---|
| P0 | 站点不可用、数据泄露、资金/询盘链路中断 | 立即响应，尽快恢复 | 需合同确认最终时限 |
| P1 | 核心流程不可用（询价、登录、发布） | 4 小时内响应（建议） | 需合同确认 |
| P2 | 重要功能异常但有替代路径 | 1 个工作日内响应（建议） | 需合同确认 |
| P3 | 一般问题、文案/样式/优化项 | 3 个工作日内响应（建议） | 需合同确认 |

最终响应时限、保修期与赔偿以合同为准；本文件不作为 SLA 承诺。

### 13.3 持续优化

- 每月复盘关键词、页面、抓取/索引、询盘与有效询盘、转化漏斗；
- 以整改单闭环，复测通过后关闭；
- 排名、流量、询盘数量作为业务观察指标，不作为固定结果验收或付款条件，除非双方另行书面约定；
- 新需求进入变更流程，不默认包含在既有报价内。
