## 1. 计划原则

1. **日期不自行承诺**：所有开始/完成日期为「待双方确认」；本合同签订、首付款到账、范围确认、客户资料到位后，才排定基准计划。
2. **工作日待评估**：阶段工作日需在 P0 基线、范围确认和 WBS 拆解后评估；当前写「待评估」，不编造。
3. **阶段门禁**：每阶段有明确交付物与验收节点，未通过不进入下一阶段（或按书面豁免处理）。
4. **付款与验收挂钩**：付款节点与可验收交付物对应；比例由合同确认。
5. **变更走书面流程**：范围、工期或费用变化须双方书面确认，不以口头或即时消息为准。

## 5. 验收流程

1. 乙方提交交付物与证据清单；
2. 客户在约定工作日内组织验收（建议 5 个工作日，待合同确认）；
3. 验收结论：通过 / 有条件通过 / 不通过；
4. 有条件通过须列明整改项、责任方与期限；
5. 不通过须列明原因与补充条件；
6. 双方签署验收记录；未签署不视为验收通过；
7. 验收通过后进入下一阶段或付款节点。

### 5.1 验收记录模板

| 字段 | 内容 |
|---|---|
| 验收对象 | 阶段/交付物名称 |
| 版本/位置 | 文档版本、代码 SHA、页面 URL、台账版本 |
| 交付方 | 乙方负责人 |
| 提交日期 | 待填 |
| 验收方式 | 文档评审 / 操作测试 / 接口测试 / 数据校验 / 抽样 |
| 验收结论 | 通过 / 有条件通过 / 不通过 |
| 缺陷与整改 | 编号、等级、责任方、期限 |
| 验收人/日期 | 客户签字 |

## 6. 缺陷分级与整改（建议值，非最终 SLA）

| 等级 | 定义 | 建议响应 | 建议修复窗口 | 说明 |
|---|---|---|---|---|
| P0 | 站点不可用、数据泄露、询盘链路中断 | 立即 | 尽快恢复 | 最终时限以合同为准 |
| P1 | 核心流程不可用（询价、登录、发布） | 4 小时内 | 当日给出方案 | 同上 |
| P2 | 重要功能异常但有替代路径 | 1 个工作日 | 约定窗口 | 同上 |
| P3 | 一般问题/文案/样式/优化 | 3 个工作日 | 纳入月度批次 | 同上 |

- 每个问题记录：ID、发现时间、等级、影响、责任方、响应时间、修复方案、完成时间、复测证据、关闭人；
- 未复测通过不得关闭；
- 开发缺陷在保修期内由乙方修复；第三方故障由供应商按条款处理，乙方协助定位；
- 客户数据错误或客户擅自修改，按合同约定处理；
- 超范围需求走变更流程。

## 7. 延期、暂停与顺延规则

| 情形 | 处理 |
|---|---|
| 客户资料/授权未按时提供 | 对应工作暂停，工期顺延；乙方书面通知 |
| 客户方决策延迟 | 受影响阶段顺延；双方确认新日期 |
| 需求变更 | 评估范围/费用/工期，书面确认后执行 |
| 第三方服务故障 | 受影响工作顺延；乙方协助定位与替代方案 |
| 不可抗力 | 按合同不可抗力条款处理 |
| 乙方原因延误 | 乙方提出追赶计划；是否承担责任按合同 |
| 付款逾期 | 乙方可暂停工作；恢复条件按合同 |

所有顺延与暂停须形成书面记录，不以口头约定为准。

## 8. 验收与上线的关系

- G7（迁移与灰度验收）通过前，不申请正式上线；

- 上线不等于项目结束；上线后进入运营期，按 OPS-01/02/03 验收；
- 生产发布授权由客户/项目负责人另行给出，本计划不构成发布授权。
