## 2. 阶段 B：兼容性改造（按顺序，不可并行）

### 2.1 改造顺序与理由

| 步骤 | 动作 | 为什么必须在这一步 | 完成判据 |
|---|---|---|---|
| B1 | Yii 2.0.44 → **2.0.55**，PHP 仍 7.4 | 先把框架兼容性单独验证，出问题只可能是框架 | 全站冒烟通过，错误日志无新增 |
| B2 | 替换 4 个停维护依赖（邮件、Excel、CKEditor、Elasticsearch 评估） | 这些包在 8.x 必炸，必须在切 PHP 前换掉 | 发信、导出、富文本编辑三条链路实测通过 |
| B3 | 测试工具链：PHPUnit 10/11、Codeception 5、移除 prophecy | 否则 CI 在 8.4 上跑不起来，等于没有回归网 | `vendor/bin/phpunit` 全绿 |
| B4 | PHP 8.4 + 依赖小幅升级（guzzle/symfony/phpspreadsheet） | 最后一步才动运行时 | staging 冒烟 + 回归通过 |

**反例（禁止）**：把 B1–B4 合成一次提交。一旦出问题，无法区分是 Yii 升级、依赖替换还是 PHP 变更导致。

### 2.2 B4 的具体改造点

| 类别 | 动作 | 验证方式 |
|---|---|---|
| 隐式可空参数 | 升 Yii 后剩余的业务代码逐个改 `?Type $x = null` | 静态扫描 + 错误日志 E_DEPRECATED 计数 = 0 |
| mysqli 异常模式 | 检查所有 `->execute()` 返回值判断，改为 try/catch | 故意制造唯一键冲突，确认被捕获而非白屏 |
| 动态属性 | 给 PHPExcel/Widget 相关类加 `#[\AllowDynamicProperties]` 或改属性声明 | 导出 Excel、打开编辑器无告警 |
| `${var}` 插值 | 全量 grep 替换为 `{$var}` | 静态扫描 0 命中 |
| `utf8_encode/decode` | 替换为 `mb_convert_encoding` | 老数据抽样比对 |
| 浮点转整型 | 价格/库存计算显式 `(int)` 或 `intdiv` | 价格页抽样 50 条与 7.4 一致 |

- **不通过**：任一核心链路（搜索/详情/询盘/后台）失败，或存在未捕获异常。

## 4. 阶段 D：并存部署与切换

### 4.1 拓扑

```
                    ┌──────────────────┐
   Nginx  ─────────▶│ upstream php74   │  ← 旧池，保留不动
                    └──────────────────┘
                    ┌──────────────────┐
                    │ upstream php84   │  ← 新池，同代码 + 8.4
                    └──────────────────┘
```

- 两套 FPM 池**并存**，同一份代码（或同一 release 目录的软链）。
- 切换只改 Nginx `fastcgi_pass` 指向，不改代码、不改数据库。
- 切换粒度：先按 cookie/内网 IP 灰度 5%，再 50%，再 100%。

### 4.2 切换前检查

- [ ] 8.4 池的 `pm.max_children` 按内存重新计算（8.4 单进程内存通常高于 7.4）
- [ ] opcache 配置对齐，JIT 关闭（先求稳）
- [ ] 日志目录可写，错误日志分开（`php84-error.log`）
- [ ] 监控已加 8.4 池的 5xx、慢请求、FPM 队列

### 4.3 回滚设计（必须演练）

| 项 | 设计 |
|---|---|
| 触发条件 | 5xx > 0.5% 持续 5 分钟；或核心链路失败 |
| 回滚动作 | Nginx upstream 切回 `php74`，**一条 reload** |
| 目标 RTO | **< 5 分钟** |
| 数据影响 | 无（PHP 版本不改变数据结构） |
| 残留风险 | 8.4 期间写入的数据（如 session 格式）需确认 7.4 可读 |
| 演练要求 | staging 至少演练 2 次，记录耗时与命令 |

> 关键前提：**不升级 MySQL、不改表结构、不改代码**，回滚才可能 5 分钟内完成。这也是"运行时升级与业务改造分开"的真正原因。

## 5. 风险登记

| # | 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|---|
| P1 | 依赖替换引入业务回归（尤其 Excel 导出） | 高 | 中 | 替换前后逐字段比对导出文件 |
| P2 | mysqli 异常模式导致未捕获异常白屏 | 中 | 高 | 全量回归 DB 错误分支；灰度期监控 5xx |
| P3 | 8.4 单进程内存上升导致 OOM | 中 | 高 | 按实测内存重算 `pm.max_children` |
| P4 | 老扩展（redis/gd/imagick）无 8.4 版本 | 中 | 高 | 阶段 A 必须拿到生产扩展清单，提前找替代 |
| P5 | 测试工具链升级后用例大量失败 | 高 | 中 | 先修用例再切 PHP，不把失败归因于运行时 |
| P6 | 灰度期缓存键冲突（两套运行时共用 Redis） | 低 | 中 | 键前缀区分或共用但格式兼容 |
